Glidex

Glidex compared

This page places Glidex next to other platforms that run virtual machines on your own hardware. It is for contributors: what Glidex does differently on purpose, and what it does not try to do.

Facts about other products are as of October 2026, checked against their official documentation and project pages (see References). Products change quickly; check the linked pages before you rely on a detail. Facts about Glidex are from this repository at the same date. A dash (—) marks a cell this page does not claim.

Positioning

Glidex is a KVM control plane written in Rust. It runs VMs on Cloud Hypervisor (the default) or QEMU, on one host or on a cluster of hosts that replicate their state with Raft embedded in the control-plane binary. One proto-defined service layer serves both a REST API and gRPC/gRPC-Web/Connect; a React web UI and the gxctl CLI use it. Networking is Open vSwitch on a host and OVN across a cluster. Authorization is Cedar policy over projects and tenants, with identities from local accounts, passkeys, OIDC providers, SCIM and directory sync.

It sits between a single-host tool and a full private cloud (OpenStack, CloudStack). It aims at labs, teams and small clouds of up to about 50 hosts, especially ones that hand out GPUs and other PCI devices. It is young (v0.0.x tags, first commit December 2025) and has fewer features than any mature product below.

Products

Proxmox VE

A Debian-based server virtualization platform for QEMU/KVM and LXC, with a web UI, a REST API, HA, SDN and broad storage support.

  • Differs: every Proxmox node is equal and ships as a distribution; Glidex installs onto an existing distro and separates server and agent roles. Proxmox has live migration, HA restart with fencing, mediated devices and many storage types; Glidex has none of these today. Glidex has tenants, Cedar policy and SCIM and directory sync built in.
  • Pick Proxmox when you want a mature, all-in-one virtualization host for a small or medium site, with VMs and containers.

OpenStack

A family of services (Nova compute, Neutron networking, Cinder block storage, Keystone identity…) that make a full IaaS cloud, run by the OpenInfra Foundation.

  • Differs: Glidex is one binary with an embedded store, not a set of services over a message queue and SQL database. It uses similar ideas at a smaller scale: OVN networks with routers, projects and quotas, federated identity. OpenStack covers far more: many hypervisor and storage drivers, vGPU, bare metal, very large deployments.
  • Pick OpenStack when you need a full cloud API, many back ends, or a large deployment with a team to run it.

oVirt and Red Hat Virtualization

oVirt manages KVM hosts from a central Engine (web UI and REST API) on PostgreSQL, with the VDSM agent on each host. Its current release is 4.5.7, and it describes itself as community-driven. Red Hat Virtualization 4.4, the product built on it, left its Maintenance Phase on 31 August 2024 and its Extended Life Phase on 31 August 2026. Red Hat points RHV users to OpenShift Virtualization.

  • Differs: oVirt keeps state in a central PostgreSQL database behind the Engine; Glidex replicates its own store with Raft and needs no external database.
  • Pick oVirt when you already run it and the community release meets your needs; former RHV customers are directed to OpenShift Virtualization.

VMware vSphere and vCenter

ESX hosts managed by the vCenter appliance, with vMotion, vSphere HA, Fault Tolerance and vSAN. Broadcom ended perpetual licensing; vSphere is sold as subscriptions, chiefly in VMware Cloud Foundation (VCF) and VMware vSphere Foundation (VVF), licensed per core.

  • Differs: Glidex runs on stock Linux and KVM, is open source and has no license cost. vSphere is far ahead on live migration, HA, storage, ecosystem and vendor support.
  • Pick vSphere when you need those operational features and vendor support, and the subscription fits.

Harvester and KubeVirt

KubeVirt adds VMs to Kubernetes as custom resources, run in pods with libvirt and QEMU. Harvester (SUSE) is a bare-metal HCI distribution built on Kubernetes, KubeVirt and Longhorn, managed alongside Rancher.

  • Differs: Glidex does not need Kubernetes; its state is in its own Raft store, and VMs are not pods. Glidex’s draft app layer (26-apps.md) would run Kubernetes on Glidex VMs, not Glidex on Kubernetes.
  • Pick Harvester or KubeVirt when your team already runs Kubernetes and wants VMs and containers under one API and toolchain.

Incus and LXD

Incus is a community-driven alternative to Canonical’s LXD, maintained by many of LXD’s original developers. Both manage system containers and VMs through a REST API, on one host or a cluster with a replicated database (Cowsql for Incus, Dqlite for LXD). Incus is Apache-2.0; LXD is AGPL-3.0 and maintained by Canonical.

  • Differs: the closest in shape: one daemon, a REST API, embedded replicated state, OVN networks. Glidex chose Raft over ReDB instead of a replicated SQL database (14-clustering.md D1), manages VMs only, offers Cloud Hypervisor as well as QEMU, and puts more into the control plane for tenants, identity and NUMA-aware device placement. Incus has containers, live migration and many storage drivers, and years of use.
  • Pick Incus or LXD when you want containers and VMs together, or a mature, packaged tool.

OpenNebula

A cloud manager with a front-end (oned, HA through Raft across front-end servers) and KVM or LXC hosts, with VDCs for multi-tenancy, LDAP and SAML sign-in, GPU passthrough and vGPU.

  • Differs: both target private clouds. Both replicate front-end state with Raft; OpenNebula replicates SQL statements to its database, Glidex replicates write sets to ReDB. OpenNebula has live migration, broad GPU support and many integrations; Glidex has a smaller feature set, REST and gRPC from one schema, and Cedar authorization.
  • Pick OpenNebula when you need a proven private cloud today.

Apache CloudStack

An IaaS platform: Java management servers on MySQL drive KVM, vSphere, XenServer/Xen, Hyper-V and other hosts, organized as regions, zones, pods and clusters, with domains, accounts and projects.

  • Differs: CloudStack supports many hypervisors and is built for multi-zone clouds; Glidex is KVM-only and much smaller.
  • Pick CloudStack when you run a multi-zone cloud for many tenants and need broad hypervisor and storage support.

MicroVM stacks (Firecracker, Kata Containers)

Firecracker is a minimal KVM-based VMM built at AWS for serverless and container services (it runs AWS Lambda and Fargate). Kata Containers is a container runtime that runs workloads in lightweight VMs, through OCI and the Kubernetes CRI, with QEMU, Cloud Hypervisor or Firecracker. Cloud Hypervisor, Glidex’s default VMM, is built on the same rust-vmm crates.

  • Differs: these are VMMs or runtimes, not control planes. Glidex manages long-lived VMs with disks, networks and devices; it does not aim at per-request VM creation or container semantics. Glidex supported Firecracker early on and dropped it for its lack of GPU passthrough (Design decisions); it may return as the VMM of a lightweight, container-compatible layer.
  • Pick them when you need sandboxed, short-lived workloads in large numbers.

Non-goals and current gaps

Non-goals (by design):

  • Automatic VM failover. A node that stops heartbeating leaves its VMs unknown; nothing restarts them elsewhere, because a partitioned node may still run them (14-clustering.md D8). Moving a stopped or lost VM is an explicit operator action.
  • Containers. Glidex runs VMs only.
  • Running on Kubernetes, or an etcd/SQL dependency.
  • An eBPF datapath (14-clustering.md D15).
  • vGPU and mediated devices (22-host-topology.md §1).

Gaps (not built yet, some planned):

  • Live migration (planned after shared datastores; 14-clustering.md §18).
  • Disk snapshots, backups, encryption at rest (24-storage.md §1).
  • Shared block storage beyond hyperstor: lvm is node-local LVM-thin; shared LVM, Ceph RBD and a CSI adapter are later milestones. Ceph is usable only as a mounted CephFS through shared-dir.
  • Serial console only: no VNC/SPICE or graphical display. Cloud Hypervisor itself runs Windows guests, but Glidex’s catalog holds Linux cloud images provisioned by cloud-init, and Windows guests are not a target today. They may come later, once the tooling supports them (a graphical console and Windows provisioning).
  • Security groups, floating IPs, BGP and load balancers (14-clustering.md §2).
  • Scale: designed for about 50 hosts and 2,000 VMs (14-clustering.md §4.1).
  • LDAP, Entra ID and GitHub connectors (19-tenancy.md T2b, T4b); directories apart from clusters and fleets (T6, T7).
  • Distribution packages: install is from source with Rust while Glidex is under active development; prebuilt binaries and distro packages are planned later.
