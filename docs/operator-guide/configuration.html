Glidex

Configuration

The control plane reads /etc/glidex/control-plane.json at start. The file is optional: without it every setting has its default, and that is how the installer leaves a host. /etc/glidex/control-plane.json.example lists every top-level setting with its default; copy it to start:

sudo install -m 0640 -o root -g glidex \
  /etc/glidex/control-plane.json.example /etc/glidex/control-plane.json
sudoedit /etc/glidex/control-plane.json
sudo systemctl restart glidex-control-plane
  • Keep the file root:glidex, mode 0640: the control plane (user glidex) must be able to read it, nobody else needs to.
  • Changes take effect on restart. Restarting the control plane leaves running VMs running.
  • The file is checked strictly. An unknown key (a typo), a wrong type or a value out of range stops the control plane with a message naming the setting; it never falls back to defaults. Read it with journalctl -u glidex-control-plane -b.
  • Every key is optional. A section you leave out, or a key inside one, keeps its default.
  • The file holds no secrets. TLS keys, the OIDC client secret and the secrets key are given to the service as systemd credentials (see Secrets).

glidex-stord

glidex-stord, the root helper behind LVM-thin datastores, reads /etc/glidex/stord.json at start (--config <path> for another file). Without the file it allows no volume group. Example

A host reached as glidex.example.org, with its own certificate and single sign-on:

{
  "server_name": "lab",
  "tls": { "cert": "/etc/glidex/tls/glidex.crt" },
  "auth": {
    "allowed_origins": ["https://glidex.example.org:5173"],
    "oidc": {
      "enabled": true,
      "issuer": "https://idp.example.org",
      "client_id": "glidex",
      "required_groups": ["glidex-users"],
      "group_teams": { "lab-staff": "staff" }
    }
  },
  "quotas": { "default": { "vms": 10, "vcpus": 32, "memory_mib": 65536 } }
}

allowed_origins here lets browsers call the API on port 8841 under that name and gives OIDC its default redirect_uri; the web UI doesn’t need it. The TLS key and the OIDC client secret are not in the file: see Secrets.

Secrets

Secrets go to the control plane as systemd credentials, never in control-plane.json, on the command line or in the environment. Keep the source files root:root, mode 0600; systemd copies each into a directory only the service can read. Add them in a drop-in:

sudo systemctl edit glidex-control-plane

[Service]
LoadCredential=tls-key:/etc/glidex/tls/glidex.key
LoadCredential=oidc-client-secret:/etc/glidex/oidc-client-secret
CredentialUsed for
tls-keyThe private key of a configured certificate (when tls.key is not set).
oidc-client-secretThe client secret of auth.oidc.
secrets-kekThe key that encrypts the secrets of login connectors made through the API. Without it the control plane keeps one in secrets.kek beside its database.

Then sudo systemctl restart glidex-control-plane.

/srv/glidex/The datastore root: registered datastores are directories under it. The installer creates it (root:root, mode 0755).

The data directory is ~/.glidex of the user the control plane runs as; for the service that user is glidex, whose home is /var/lib/glidex-control-plane. The service can only write inside that home, so image and disk directories, and files you give the API by path, must be inside it or readable by glidex outside /home, /root, /run/user and /tmp.

A control plane you start by hand uses your own ~/.glidex and the run directory $XDG_RUNTIME_DIR/glidex (else /tmp/glidex-<uid>).

For example, to serve the UI on one address under a DNS alias:

[Service]
Environment=GLIDEX_UI_LISTEN=192.0.2.10:5173
Environment=GLIDEX_UI_HOSTS=glidex.example.org,192.0.2.10

Behind a reverse proxy or a tunnel that runs on the host (such as cloudflared), list the public name users open in GLIDEX_UI_HOSTS, with the host’s own names if people still use them: the variable replaces the default list. (On a cluster server, cluster.ui_url’s name is accepted without it.) Also set GLIDEX_UI_CLIENT_IP_HEADER, so the audit log and rate limits see each browser’s address instead of 127.0.0.1:

[Service]
Environment=GLIDEX_UI_HOSTS=glidex.example.org,host.example.org
Environment=GLIDEX_UI_CLIENT_IP_HEADER=CF-Connecting-IP

See Behind a load balancer or tunnel for what else a proxy in front of several servers needs.
