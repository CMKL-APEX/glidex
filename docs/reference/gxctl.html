Glidex

gxctl

gxctl is the Glidex command-line client. It runs as an interactive shell, or runs one command and exits:

gxctl                                   # interactive shell: gxctl> …
gxctl list                              # one command, then exit
gxctl --project lab disk list
gxctl --url https://host.example.org:8841 auth login --oidc

In the shell, help (or ?) lists the commands, Tab completes command names, subcommands and file paths, and exit (quit, q) leaves. Words can be quoted: project create lab --description "Lab VMs". Noun commands also answer to their plural (images, projects, tenants, …), and many subcommands to short forms (ls, rm).

gxctl --help shows the global options. Commands have no --help of their own: run one without its arguments to see its usage line, or gxctl help for the full list. Both are authoritative over this page.

Connecting and logging in

  • On the host, gxctl uses the Unix socket and you are your Unix user: no login. You need to be in glidex-users (or glidex-admin for administration).
  • From another machine, log in once with auth login, which saves a profile (target URLs, TLS trust and token) in ~/.config/glidex/config.json (mode 0600). Later runs use the current profile. The older login command saves just a token in ~/.config/glidex/token.
  • A self-signed server certificate is either trusted through GLIDEX_CA_CERT, or pinned by fingerprint at auth login (compare it with the one the server printed at start).
  • On a cluster agent, which has no API of its own, other commands fail with this host is a cluster agent: it has no local API; auth login, auth use, auth profiles and auth trust still run. Log in to a server: gxctl auth login --url https://<server>:8841.
